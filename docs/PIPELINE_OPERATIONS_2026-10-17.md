# 每日流程的執行證據

上一版只能看到排程是否啟用，無法由 API 確認最近一次是否成功。本次新增持久化流程紀錄與 `/pipeline/status`，不修改預測規則、模型或事前驗證組別，也不補造過去流程的執行紀錄。

## 保存與互斥

- 每次執行產生獨立 run_id，記錄實際開始／完成時間、manual／scheduled 觸發來源、目前步驟及各步驟回傳碼。
- 紀錄保存在現有持久磁碟 `models/artifacts/operations/`；按 run_id 保留每次紀錄，另有最新流程與最後完整成功的索引。寫入採暫存檔、fsync 與原子替換。
- 同一磁碟的檔案鎖涵蓋整個流程，防止 API 排程、獨立排程與手動執行重疊。拿不到鎖的呼叫回報 ALREADY_RUNNING，不覆寫正在執行的紀錄。
- API 查詢只讀現有紀錄，不建立檔案、不改寫失敗狀態，也不啟動或重跑流程。
- 每個資料子步驟繼承鎖描述符；即使主流程突然死亡，仍在執行的子步驟會持續持鎖，避免新流程重疊。所有持鎖進程結束後鎖才釋放；若最後紀錄仍為 RUNNING 而已無鎖，API 顯示 INTERRUPTED。這是依執行狀態推導，不把未知結果改成成功。

## 狀態意義

| 狀態 | 意義 |
|---|---|
| NO_RECORD | 尚無這版監控的紀錄，不能推斷舊版從未執行 |
| RUNNING | 流程持有鎖，可查看目前步驟 |
| SUCCEEDED | 最近一次流程所有步驟回傳 0；非必要來源降級仍須併看資料品質與來源日誌 |
| FAILED | 最近一次有非零回傳碼或程式例外，保留上次完整成功紀錄 |
| INTERRUPTED | 中斷或進程已消失，沒有確認完成 |
| STALE | 最新紀錄曾成功，但最近應執行週期在期限內沒有新的完整成功 |
| STATE_ERROR | 執行紀錄損壞或無法讀取，避免顯示假成功 |

預期排程為每日 22:30 UTC；完成期限為該次預期時間加四小時，涵蓋六步驟各 30 分鐘上限與一小時排程延遲容許值。失敗／中斷會立即顯示，不必等待逾期。`overdue` 另表示最近到期週期沒有完整成功。

排程的 misfire_grace_time 為一小時；這只能處理進程仍在時的延遲，不會在容器關閉後自動補跑所有錯過的工作。逾期監控可辨識這個缺口，但本次沒有啟用對外告警或自動發送 LINE。

儀表板會顯示最近更新狀態與最後完整成功時間；執行成功與預測到期評分是兩件事，不能因此解除選時建議的驗證限制。

## 驗證

新增測試涵蓋讀取不建立檔案、逐步進度、失敗保留上次成功、空流程不製造成功、真實跨進程互斥、進程死亡辨識、逾期與損壞紀錄，以及 API 唯讀。例外只保存類型，不保存可能包含敏感內容的錯誤訊息。

GitHub 已確認前一個 commit `e76cdb7` 的 [CI 通過](https://github.com/Andrewweng0406/Currency-Exchange/actions/runs/39012674676)。本次變更有 165 項測試通過，並在部署的 Linux 環境完成相同測試；儀表板以 AppTest 驗證可正常顯示執行狀態。
